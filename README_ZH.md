# OfflineSkins（中文说明）

让**离线模式的服务器**与**单人游戏**也能显示玩家真实的**皮肤与披风**；Tab 列表头像、玩家头颅与人体模型也会使用这些皮肤。（**人体模型**是原版的一种装饰性实体：外形与玩家相同、会显示所给档案的皮肤 —— 可用 `/summon minecraft:mannequin ~ ~ ~ {profile:"<玩家名>"}` 生成。）

只需要装在客户端：**服务端不需要安装，也不需要任何配置**。拿不到皮肤数据时它完全不介入，表现与原版一致。

## 开始前

- Minecraft **26.2** 与 **Fabric Loader**
- 需要再装 **Fabric API** 与 **Cloth Config**
- **Mod Menu 是可选的** —— 装了才有图形化的配置入口；没装也能用 `/offlineskins reload`，或直接改配置文件

## 安装

把本模组的 jar 放进客户端的 `mods/` 目录即可。

## 放皮肤与披风

文件放在游戏目录下的 `config/offlineskins/`（正式客户端即 `.minecraft/config/offlineskins/`），首次启动会自动创建：

```
config/offlineskins/
├── config.json
├── skins/
│   ├── <玩家名>.png
│   └── uuid/<32位无横线小写UUID>.png
└── capes/
    ├── <玩家名>.png
    └── uuid/<32位无横线小写UUID>.png
```

- **按玩家名**：`<玩家名>.png`，**离线名同样可用**；名字要与游戏里显示的一致（Linux 上区分大小写）。
- **按 UUID**：`uuid/` 目录下的 `<32位无横线小写UUID>.png`（例如 `0123456789abcdef0123456789abcdef.png`）—— 只有"档案本身已是正版 UUID"时才会先查它。
- **图片要求**：64×64 直接使用；64×32 会自动补全成 64×64（旧版皮肤）；其它尺寸会被忽略。只接受 PNG。

## 配置

`config/offlineskins/config.json`（首次启动自动生成）：

| 选项（JSON 键）                        | 默认 | 作用                                                   |
|----------------------------------------|------|--------------------------------------------------------|
| 使用官方皮肤源（`mojangSource`）       | 开   | 从 Mojang 获取正版玩家的皮肤与披风；关掉后只认本地文件 |
| 停用头颅覆盖（`disableSkullOverride`） | 关   | 打开后，头颅、头颅物品与人体模型一律交回原版渲染       |
| 后台工作线程数（`workerThreads`）      | 8    | 取值 1–32；多人服首次进场加载慢时可以调大              |

- 装了 **Mod Menu** 的话，可在 **Mod Menu → OfflineSkins → 配置** 里直接修改，保存后立即生效并写回文件；
- 也可以手改 JSON，然后用 `/offlineskins reload` 使其生效（或重启游戏）；
- 配置里缺失的选项会在启动时自动补进文件；你已有的值和自加的其它键不会被覆盖。

## 命令

| 命令                   | 作用                                                              |
|------------------------|-------------------------------------------------------------------|
| `/offlineskins status` | 查看当前配置、线程数、皮肤与披风服务的统计，以及 5 处挂钩是否正常 |
| `/offlineskins reload` | 重新读取配置并立即生效                                            |
| `/offlineskins clear`  | 清空皮肤缓存与纹理（下次渲染时重建）                              |

## 优先级与更新时机

- **官方皮肤优先于本地文件**：本地文件先就绪就先显示本地，官方数据到达后自动升级；官方拿不到（非正版名、断网等）就一直用本地文件。
- 皮肤只在内存中缓存，**官方皮肤不写磁盘**，下次进游戏重新获取。
- **失败会自动重试**：约 5 秒起、逐步退避到最长 160 秒，**不用退出世界**；本地文件是后来才放进去的也会被自动识别。

## 为什么我的皮肤没生效

1. 文件放在 `<游戏目录>/config/offlineskins/skins/` 了吗？
2. 文件名与游戏内玩家名完全一致吗？（Linux 区分大小写）
3. 是 64×64 或 64×32 的 PNG 吗？
4. 该玩家名是正版名吗？若是，官方皮肤会覆盖本地文件 —— 想让本地优先，可放到 `skins/uuid/<正版UUID>.png`，或临时关掉官方源来验证。
5. 只有头颅或人体模型不生效？检查"停用头颅覆盖"是否被打开了。
6. 仍然不行：用 `/offlineskins status` 查看统计，并把 `logs/latest.log` 里含 `OfflineSkins` 的行发给维护者。需要更详细的日志时，可在启动参数里加 `-Dfabric.log.level=debug`。

## 有些玩家的皮肤不是本模组给的

只有 `/offlineskins status` 里显示「**就绪**」的玩家才是本模组提供的；显示「**无数据**」的玩家本模组完全没有参与 —— 他们身上的皮肤（或默认皮肤）来自**原版**，也就是服务器下发的档案。常见情形：服务器插件或代理下发了真实档案；以及 **Carpet 假人**（假人的名字若是正版账号，服务器解析出的档案自带皮肤信息，原版就会画出真实皮肤）。

最彻底的验证方式：把本模组的 jar 移出 `mods/` 再进同一台服 —— **皮肤不变即与本模组无关**。

## 与其它模组的兼容性

本模组会改动皮肤的获取与显示入口。若同时安装其它皮肤类模组（例如 CustomSkinLoader、Ears、Figura 等），可能互相覆盖，表现为部分皮肤不生效、被换成另一张、或来回闪烁。本模组**不做检测、也不做互斥处理**，排查顺序：

1. 先只留本模组，确认它单独工作正常；
2. 再逐个装回其它模组，定位冲突方；
3. 两者都要用时，用各自的配置关掉重叠部分（例如用"停用头颅覆盖"关掉本模组的那部分）。
